═══════════════════════════════════════════════════════════════════════
LABELING DEMO — Peeling a Honeycrisp Apple (complete run)
═══════════════════════════════════════════════════════════════════════

INSTRUCTIONS

You are a labeling engine for 3D scene elements. Given a set of objects
and their elements, assign a semantic label to each element based on its
geometry and the context provided in the input.

Rules:

- Every element receives exactly one label.
- Labels are short, lowercase, words joined by underscores when needed.
- The label should describe the role the element plays in the object,
  not just its geometric type. For example, a sphere inside an apple is
  not "sphere", it is "skin" or "flesh" depending on what it represents.
- If the element's role cannot be determined from the input, fall back
  to its geometric type (for example: "sphere", "cylinder").
- The input may include current material and metadata (properties like
  skin_present, state, moisture) so the label reflects the element's
  current role, not just its geometry. For example, an apple sphere with
  skin_present: false should still be labeled "skin" (the shell is still
  geometrically present even though the property says it has been
  removed) unless the element is clearly the exposed interior, in which
  case the label is "flesh".
- For split or clipped objects, the elements are inherited from the
  source but the visible surface includes cut faces. The labels should
  reflect the roles that the elements play in the split object, not the
  roles they had in the source.
- Object groups with multiple similar elements (for example, a group of
  seeds) should be labeled with the same role name; if the individual
  elements are distinguishable, append an index (seed_1, seed_2, ...).
- Output JSON with a single key "labels" containing a list of
  {object_id, element_index, label} entries, plus a "notes" string.

When labeling is called:

- The pipeline calls the labeling engine once at t=0 (initial scene) and
  once after any top-level action that introduces at least one new
  object or new element. Top-level actions that only move, rotate, or
  change properties of existing objects do not trigger a call.
- In the apple-peeling memory, the calls are triggered by: the initial
  scene, and after H2, H6, H7, H8, H9, H10, and H12. All other actions
  (H1, H3, H4, H5, H11, H13, H14) do not trigger a call.
- Transient objects that are created and removed within the same
  top-level action (for example, water_stream_01 in H2, and the two
  apple halves in H9) are labeled while they exist, but their labels are
  discarded when the object is removed. They still appear in the
  labeling call because they are present in the frame at the moment the
  call is made.
- Element indices are relative to the object's current element list at
  the time of the labeling call. If an object gains or loses elements
  over time, the same label may move to a different index in a later
  call.

Output format (exact):

{
  "labels": [
    {"object_id": "...", "element_index": 0, "label": "..."},
    {"object_id": "...", "element_index": 1, "label": "..."},
    ...
  ],
  "notes": "..."
}
