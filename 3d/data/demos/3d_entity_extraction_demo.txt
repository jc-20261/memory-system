ENTITY EXTRACTION DEMO — Peeling a Honeycrisp Apple
═══════════════════════════════════════════════════════════════════════

The user message contains four blocks:

1. The natural language memory.
2. The memory sketch (initial object list and action plot).
3. The enhanced sketch (extended object list and decomposed actions).
4. The parts prior (exhaustive expected parts per object).
5. The state-annotated action timeline (with preconditions, changes,
   sensory effects, natural process links).

The task is to produce a single JSON object with three top-level keys:
"protagonist", "objects", and "actions".

Rules, restated from the system prompt:

- Only include objects present at the START of the memory (t=0). Do not
  include objects created by actions later in the memory.
- Use obj_ids of the form <template>_<NN> or role-specific names for
  compound objects.
- Preserve the composite hierarchy from the sketches.
- Only list top-level human actions, not natural processes or
  sub-actions.
- Output only valid JSON.

DEMONSTRATION:

Below is the expected output for the apple-peeling memory. It was
produced from the memory sketch, enhanced sketch, parts prior, and
state-annotated sketch shown elsewhere in the demos.


Note on the output below (do not output these notes, these are just some more guidelines):

- Objects created mid-memory are deliberately excluded: peel_strip_01,
  apple_flesh_exposed_01, juice_01, juice_on_hand_01, apple_half_*,
  apple_quarter_*, apple_core_a_01..d_01, apple_seeds_01, water_stream_01.
  These will be added by Stage 4 operations.
- The composite sub-objects of the apple (apple_skin_01, apple_flesh_01,
  apple_core_01) are included because they exist from the start as parts
  of the apple, even though the scenes do not physically separate them
  until later.
- The destination bowl (bowl_destination_01) is included because it is a
  static object in the kitchen, even though it is only used in H12.
- bowl_source_01 and bowl_destination_01 share a template ("bowl") but
  have distinct obj_ids, matching the scene demo's naming.
- The top-level actions are the 14 H-lane actions from the annotated
  sketch. Natural process lanes (N1 through N14) are not listed as
  top-level actions; they will be handled at Stage 4 as change_properties
  and emit_event operations.
