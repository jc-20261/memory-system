OPERATIONS DEMO — Peeling a Honeycrisp Apple

CALL STRUCTURE

This file demonstrates the format for one Stage 4 call. Each numbered
section below (H1 through H14) is a separate call. A single call receives
one top-level action from the annotated timeline, and returns one JSON
object with a single "operations" key and a "notes" key.

The sections are ordered by the sequence of top-level actions in the
apple-peeling memory, but each section is independent: it is the expected
output for exactly one call, not a single response covering all actions.

EXPECTED OUTPUT SHAPE

Each call returns exactly one JSON object, nothing else:

{
  "operations": [ {...}, ... ],
  "notes": "..."
}

No section headers, no prose before or after, no wrapper object.

ELEMENT LABELING

Every element inside an add_object or add_element operation must carry a
material_override dict with a label field. The label names the semantic
role of that element within its containing object. Labels are lowercase
and use underscores when needed (stem, calyx, blade, handle, seed_1).

Labels describe intrinsic composition, not current state. A sphere that
represents the apple's skin is labeled "skin" whether or not the skin is
currently present.

Objects that already exist do not need to be relabeled when their
properties change. Labels are assigned when an object or element is
created.

OPERATION VOCABULARY

Geometric operations:
  move              additive translation (object_id, delta)
  rotate            multiplicative rotation (object_id, quaternion)
  scale             multiplicative scale (object_id, factor)
  set_transform     set full world TRS in one shot
  attach            make A a child of B in the scene graph
  detach            make A independent of its current parent
  split             binary split of one object into two along a plane
  merge             combine N objects into one
  add_object        introduce a new object with labeled elements
  remove_object     remove an object entirely
  add_element       add a primitive element to an existing object
  remove_element    remove a primitive element

Property and interaction operations:
  change_properties merge or replace an object's property dict
  contact           record a physical contact interaction
  release           terminate a prior contact
  label             assign a semantic label to an object or element
  unlabel           remove a semantic label
  wait              advance time without geometry change
  emit_event        record a perceptual or semantic marker
  compound          group several operations under one action

CONTACT AND RELEASE

contact and release model physical interaction. They are distinct from
attach and detach, which control the scene-graph hierarchy.

  attach / detach  – "if the parent moves, does the child follow?"
  contact / release – "is A touching B, and how?"

ContactOp fields:
  object_a         actor or subject of the contact
  object_b         object being contacted
  contact_type     touch, grip, hold, push, pull, lean, support, rest_on
  contact_points   optional list of {point_world, normal_world}
  force            placeholder dict; defaults {"magnitude_n": 0.0,
                   "direction_world": [0,0,-1]}
  friction         placeholder dict; defaults {"coefficient": 0.5,
                   "regime": "static"}
  starts_contact   True for a new contact
  ends_contact     True for ending an existing contact
  participants     semantic roles
  notes            optional string

CONTACT-TYPE-TO-ATTACHMENT CONVENTION

  contact type   implies attachment?
  ------------   -------------------
  touch          no
  grip           yes
  hold           yes
  push           optional
  pull           optional
  lean           no
  support        no
  rest_on        no

When you emit a ContactOp with type grip or hold, also emit the matching
attach in the same OperationGroup, unless the objects are already attached
in the current hierarchy. When you emit a release that ends a grip or hold,
also emit the matching detach.

PHYSICS PLACEHOLDERS

The force and friction sub-dicts of a contact are placeholders for a
future physics addon. Values are recorded but not consumed. Do not invent
units or fields beyond those listed.

CYCLICAL ACTIONS

Cyclical actions are expanded cycle by cycle. Each cycle is one compound
operation whose sub-operations are the per-cycle leaf actions.

OPERATION FIELDS

  move:              object_id, delta
  rotate:            object_id, quaternion
  scale:             object_id, factor
  set_transform:     object_id, world_transform
  attach:            child_id, parent_id, preserve_world, snap_local
  detach:            child_id
  split:             source_id, cut_point_world, cut_normal_world,
                     new_object_ids, children_assignment
  merge:             object_ids, new_object_id
  add_object:        object_id, template_name, elements, material,
                     object_transform, parent_object_id, mass_grams
  remove_object:     object_id
  add_element:       object_id, element
  remove_element:    object_id, element_index
  change_properties: object_id, properties, merge
  contact:           object_a, object_b, contact_type, contact_points,
                     force, friction, starts_contact, ends_contact,
                     participants, notes
  release:           object_a, object_b, participants, notes
  label:             object_id, label, element_index
  unlabel:           object_id, element_index
  wait:              duration, note
  emit_event:        event_type, payload
  compound:          label, operations, participants
